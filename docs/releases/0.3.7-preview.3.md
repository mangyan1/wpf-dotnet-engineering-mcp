# Engineering MCP 0.3.7-preview.3

This pre-release removes application-specific coupling and makes workspace authorization universal for modern and classic WPF applications, including WPF-UI Fluent applications.

## Universal WPF authorization

- Replaced the product-specific Control Center action with **Authorize WPF workspace**.
- Discovers built executable projects with `UseWPF=true` and classic WPF project-type metadata.
- Supports multiple WPF applications under one selected solution or repository.
- Creates a distinct durable policy for each workspace using a sanitized name and canonical-path hash.
- Authorizes exact executable names and paths while keeping network access, destructive actions, and privileged diagnostics denied.
- Enables redacted screenshots, PII masking, audit recording, source access limited to the selected root, and the generic WPF/diagnostic tool profiles.

## Discovery hardening

- Discovery is read-only and does not execute MSBuild or project imports.
- Scans are bounded to 4,096 directories, 256 projects, and 64 WPF applications.
- Build, object, vendor, Git, artifact, and reparse-point directories are excluded.
- Authorization fails closed for drive roots, unbuilt WPF applications, excessive workspace breadth, and ambiguous executable names.
- Reads safe, literal, in-workspace `Directory.Build.props` and imported property files without executing MSBuild.
- Offers a manual executable fallback that verifies managed WPF references and rejects paths outside the workspace or through reparse points.
- A static product-neutrality gate prevents application-specific names or paths from returning to the universal MCP package.
